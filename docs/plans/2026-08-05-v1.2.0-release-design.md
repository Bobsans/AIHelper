# AIHelper v1.2.0 Release Preparation Design

## Scope

Prepare the complete repository state since `v1.1.0` as `v1.2.0`, including
the 76 committed changes and the authoritative current working tree. This phase
does not authorize a commit, push, workflow dispatch, tag, or GitHub Release.

## Evidence Model

Use the complete `v1.1.0` to working-tree diff as the source of truth. Group
implementation, tests, and documentation into observable user or operator
outcomes instead of deriving release claims from commit subjects alone. The main
release themes are managed MCP lifecycle, asynchronous MCP execution and
shutdown, signed release assets, Windows self-update and rollback, runtime
improvements, and updater review fixes.

## Release Changes

- Set every workspace package and corresponding local `Cargo.lock` entry to
  `1.2.0`.
- Set the signed manifest compatibility floor to `1.2.0`, the first release that
  contains the updater protocol.
- Move verified `[Unreleased]` outcomes into `## [1.2.0] - 2026-08-05`, retain
  an empty `[Unreleased]`, and update comparison links.
- Draft GitHub release notes from the same verified outcomes. State that users
  must install `v1.2.0` manually from `v1.1.0`; built-in updates begin with the
  updater shipped in `v1.2.0`.

## Validation

Require one `1.2.0` version across all detected workspace packages, no stale
local package versions, a clean release diff, formatting, full workspace tests,
locked debug and release builds, and the existing workflow contracts. Preserve
all pre-existing working-tree changes and stop before publication actions.
